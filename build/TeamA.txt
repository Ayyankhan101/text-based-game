Wolf Pack Survival Adventure Game
Data Structures Lab Final Project
Project Overview
Build an Interactive Text-Based Wolf Survival Game where players control a lone wolf
navigating through a dangerous wilderness. The game features story-driven decisions, resource
management, combat encounters, pack dynamics, and multiple endings. This project demonstrates
how data structures power game mechanics, AI decision-making, and narrative branching.

Game Story & Setting
Background:
You are a young wolf separated from your pack during a harsh winter storm. You must survive in
the wilderness, make critical decisions, build alliances, and find a new pack or establish your own.
Every choice matters - some lead to survival, others to doom.

Game Objectives:
•
•
•
•
•
•
•

Survive 30 days in the wilderness
Maintain stats: Hunger, Health, Energy
Make decisions that affect story outcome
Collect resources: Food, herbs, territory knowledge
Build pack: Recruit wolves, establish hierarchy
Face threats: Bears, rival packs, hunters, harsh weather
Multiple endings: Alpha wolf, lone wanderer, tragic death, etc.

2. Wolf Character & Stats Management
•
•
•
•

Health: 0-100 (dies at 0)
Hunger: 0-100 (dies if reaches 100)
Energy: 0-100 (affects success rates)
Reputation: 0-100 (affects pack interactions)

Stats Management:
•
•
•
•

Hunger increases by 5 every decision/action
Health decreases if hunger > 80
Energy decreases with activities, restores with rest
Stats affect available choices and success probabilities

Implement using: Simple struct/class with validation
3. Inventory System
• Store items: Food (meat, berries), Herbs (healing), Territory Maps
• Implement using Singly Linked List (dynamic size)
• Each item has: Name, Type, Effect, Quantity
Example Items:
- Rabbit Meat: Reduces hunger by 30
- Healing Herbs: Restores 20 health
- Territory Map: Reveals safe paths
- Wolf Scent: Helps recruit pack members

Operations:
•
•
•
•
•

Add item to inventory
Use item (remove from inventory, apply effect)
Display all items
Check if item exists
Maximum 10 items (full inventory)

4. Threat & Event System
• Random events occur based on decisions and time
• Implement using Priority Queue (Min Heap)
• Events have priority levels:
• Priority 1 (Critical): Bear attack, hunter nearby
• Priority 2 (Urgent): Severe hunger, injury worsening
• Priority 3 (Normal): Weather change, prey spotted
Event Processing:
•
•
•
•

Higher priority events trigger first
Events can chain (bear attack → injury → need healing)
Some events are time-based (every 5 decisions)
Display warning before critical events

5. Pack Management (Optional but Recommended)
•
•
•
•

Recruit other wolves to form pack
Each wolf has: Name, Role (Hunter/Scout/Guard), Loyalty
Store pack members in Linked List
Pack benefits:
• Hunting success rate increases
• Protection from threats
• Shared resources
• Pack challenges:
• Must feed all members
• Loyalty decreases if hunger is high
• Alpha challenges from strong wolves
6. Game State History
•
•
•
•

Track previous game states for undo/back functionality
Implement using Stack
Store: Current scenario, stats, inventory, day number
Operations:
• Save state before each decision
• Undo last decision (pop from stack, restore state)
• Clear history
• Maximum 5 undo levels

7. Action Queue
•
•
•
•
•

Some actions take multiple turns (hunting, traveling)
Implement using Queue
Example: "Hunt deer" → Queue [Track → Chase → Kill → Eat]
Process one action per turn from queue
Display ongoing action progress

// Pseudo-code for decision processing
void processDecision(Choice choice) {
// Save current state to stack
gameHistory.push(currentState);
// Move to next node in decision tree
currentNode = (choice == A) ? currentNode->left : currentNode->right;
// Apply stat changes
updateStats();
// Check for triggered events
checkEvents();
// Generate random encounters based on probability
if(random(0, 100) < encounterChance) {
triggerEvent();
}
// Increment day
dayCounter++;
}

Prompt Engineering Guide
Bad Prompts:
"Make wolf game"
"Decision tree code"
"Game GUI"

Good Prompts:
For Binary Decision Tree:
"Create a Binary Tree in C++ for a story-based game. Each node
has: scenarioID (int), description (string), choiceA_text (string),
choiceB_text (string), and pointers to left and right children
(next scenarios). Leaf nodes represent endings. Implement insert(),
traverse(), and getCurrentChoices() functions. Show how to build
a sample tree with 5 nodes."

For Priority Queue Events:
"Implement a Min Heap Priority Queue for game events. Each event
has: eventName (string), priority (1-3, lower is more urgent),
description (string), and effect on stats (struct). When player
takes an action, check if events should trigger. extractMin()
should return the highest priority event. Show insert and
extractMin with example events like 'Bear Attack' (priority 1)
and 'Found Berries' (priority 3)."

For Game State Stack:
"I need to implement undo functionality in my game using a Stack.
Each state contains: currentNodeID (int), health (int), hunger (int),
energy (int), inventoryList (linked list pointer), dayNumber (int).
When player makes a decision, push current state. When player presses
undo, pop and restore previous state. Implement push, pop, and
restoreState functions. Handle empty stack case."

For Linked List Inventory:
"Create a Singly Linked List for game inventory. Each item node
has: itemName (string), itemType (enum: FOOD, HERB, TOOL), effect
(int), quantity (int). Implement addItem(), useItem(itemName),
removeItem(), displayInventory(), and checkIfFull() functions.
Maximum 10 items allowed. Show how using an item removes it from
list and applies its effect to player stats."

For Story Writing:
"Help me write a branching story scenario for a wolf survival game.
The wolf is lost and starving. Create one scenario node with:
1. Detailed description (3-4 sentences) setting the scene
2. Two meaningful choices that affect gameplay differently
3. Consequences for each choice (stat changes, new situations)
Make it immersive and realistic to wolf behavior. Include survival
elements like hunger, danger, and territory."

Sample Story Scenarios
Scenario 1: The Beginning
"You wake up disoriented. The storm has passed, but you're alone.
Your pack is nowhere to be seen. Snow covers everything, and your
stomach growls with hunger. In the distance, you smell something fresh blood. But approaching means leaving the area where your pack
might return."
Choice A: "Follow the scent of blood (Hunt)"
→ Leads to hunting scenario
→ Energy -10, might find food
Choice B: "Wait here and howl for your pack"
→ Leads to waiting scenario
→ Energy -5, might encounter rival pack

Scenario 2: The Hunt
"You track the blood scent to a frozen stream. A wounded deer stands
on the other side, weak and vulnerable. Easy prey. But the ice looks
thin - it might not support your weight. You could also try to find
another way around."
Choice A: "Cross the ice carefully"
→ 70% success rate if energy > 50
→ Success: Get deer (-50 hunger)
→ Fail: Fall through ice (-30 health, -20 energy)
Choice B: "Find another way around"
→ Takes 2 turns (queue: Move → Move → Hunt)
→ Deer might escape (50% chance)
